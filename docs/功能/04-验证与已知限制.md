## 2. 环境依赖

- JDK 25（Temurin，最低标准）+ Maven 3.9+（仓库自带 `mvnw`）。
- PostgreSQL 16+、pgvector、Redis 7+；本地规划用 `deploy/docker-compose.dev.yml` 一键创建（含 RustFS，凭据走 `deploy/.env`）。
- 本地开发对象存储：RustFS（S3 兼容，Docker 运行）；线上为 Cloudflare R2。两者共用 AWS SDK for Java v2 实现。
- mica-ai-face 模型（`model-tools/face/models/` 下 5 个 ONNX，随上游仓库分发、不入 jar）：
  `face_detection_yunet_2023mar.onnx`、`face_recognition_sface_2021dec.onnx`、`2.7_80x80_MiniFASNetV2.onnx` 等，路径必须显式配置。
- mica-ppocr 模型（PP-OCR 检测 + 识别）。
- ONNX Runtime 1.18.0 与 OpenCV 4.9.0（openpnp 发行，含 macOS/Windows/Linux 原生库）由 mica-ai 传递引入。
- 摄像头与可用的浏览器；`getUserMedia` 需要 `localhost` 或 HTTPS。
- Docker（Apple Silicon 使用 linux/arm64 镜像）。

## 3. 已知限制

| 限制                    | 影响                                                                       | 处理                                                |
|-------------------------|----------------------------------------------------------------------------|-----------------------------------------------------|
| mica-ai-face 社区较新   | 2026-11-14 约 29 stars，踩坑参考少，API 可能变化                           | 锁定版本、审读关键源码、建立升级评估与回归测试      |
| 开源静默活体泛化有限    | MiniFASNetV2 为轻量模型（80x80 输入），对屏幕翻拍、打印、Deepfake 防御有限 | 挑战动作、频控、设备风控、人工复核兜底              |
| ONNX CPU 推理吞吐有限   | 单实例并发受 CPU 限制                                                      | 有界队列 + 多实例扩容；必要时 `device=gpu`          |
| OCR 不验证证件真伪      | 不能替代证件防伪                                                           | 规则校验 + 人工复核 + 明确对外口径                  |
| 1:N 误识别风险          | 大 gallery 下误命中后果高                                                  | 阈值 + margin + 近似阈值转人工                      |
| 模型权重许可证          | eDifFIQA-Tiny 为 CC-BY-4.0（商用需署名），其余需逐个核对                   | 建立 `MODEL_LICENSES.md`，随模型入库                |
| mica-ppocr 许可证待核验 | 搜索结果显示 Apache/MIT 倾向，未直接核验仓库 LICENSE                       | 落地 OCR 前核对 `mica-ppocr` 仓库 LICENSE 与 NOTICE |
| 生物特征合规            | 同意、留存、删除、跨境要求                                                 | 租户级同意记录、最小化、加密、可删除                |
| 新栈未实测              | Spring Boot + mica-ai-face 链路无任何实测数据                              | 按需求 0001 验收清单逐项执行                        |

## 5. 后续复现步骤

1. 准备 JDK 25 与 Maven（或直接用仓库 `./mvnw`），创建多模块 `pom.xml` 骨架。
2. 启动 `deploy/docker-compose.dev.yml`（数据卷首次初始化自动执行 `docs/需求/0001/sql/` 下的 DDL）。
3. 配置 `mica.ai.face.model.*` 模型路径（真实引擎，无 Mock），以 `dev` profile 启动服务，打通 JWT、challenge、上传与审计。
4. 用真实人脸样本验证检测、活体、1:1 与 1:N。
5. 用证件样本验证 mica-ppocr 字段抽取与规则校验。
6. 运行 `./mvnw -DskipTests package`、`./mvnw test`、两个文档校验脚本与 Mermaid 渲染，记录实际结果。

## 6. 安全与凭据

- 文档只写配置字段名，不写真实连接串、密钥或 token。
- `/dev/token`、`/dev/face-test.html` 只允许 dev profile，生产配置出现 `auth.enable-dev-token=true` 即视为缺陷。
- 接入真实样本前，先确认样本脱敏与留存期限。
