# 0001 人脸核验平台 — 需求清单

> 来源：需求方 2026-11-14 口头提出（人脸 KYC 与敏感操作人脸核验，建设通用人脸核验平台）
> 分支：N/A（独立新项目，尚未初始化 Git）
> 日期：2026-11-14
> 修订：2026-11-14 技术栈由 C#/.NET 切换为 Spring Boot + mica-ai-face（决策与评估见方案评估）
> 状态：设计稿，待评审

## 1. 背景与目标

现有 `cpay-api` 的人脸认证是“上传照片 + 后台人工审核”，缺少自动活体与比对能力。业务需要在 KYC
首次认证和提现、改密、大额支付、支付方式变更等敏感操作前，增加可复用的自动人脸核验能力。

目标：

- 建设一套独立部署、内部多业务共用的人脸核验服务；
- 覆盖无状态 1:1、静默活体、人脸档案 1:1、1:N 检索和证件 OCR；
- 业务侧通过统一 RN 组件 + 短期 JWT 接入，不重复实现采集与判定；
- 所有能力免费开源，不引入商业授权或按次计费依赖。

## 2. 本期范围

| 编号  | 能力         | 说明                                                          |
|-------|--------------|---------------------------------------------------------------|
| FR-01 | 多租户与鉴权 | 租户注册、服务间签名、端上短期 JWT、jti 防重放                |
| FR-02 | 挑战下发     | 动作、帧数、nonce、过期时间，绑定 tenant/sub/scene/ref/device |
| FR-03 | 无状态 1:1   | 参考图 + 现场帧比对，不落库，用于 KYC 人证比对                |
| FR-04 | 静默活体     | 基于连续帧判断真人或攻击介质                                  |
| FR-05 | 人脸档案     | 加密特征录入、更新、查询、删除                                |
| FR-06 | 档案 1:1     | 现场帧与已录入档案比对，用于敏感操作                          |
| FR-07 | 1:N 检索     | 在指定 gallery 内检索候选，返回 topK、分数与 margin           |
| FR-08 | 证件 OCR     | 证件字段识别、模板抽取、校验位/MRZ/有效期规则                 |
| FR-09 | 人证 1:1     | 证件头像与现场活体帧比对，可与人证流程组合                    |
| FR-10 | 结果令牌     | 平台签发一次性 `verification_token`，业务后端验签并消费       |
| FR-11 | 统一 RN 组件 | 相机采集、动作提示、challenge、上传、错误映射                 |
| FR-12 | 本地 H5 验证 | 仅 Development 的采集页与 DevToken，用于本地联调              |
| FR-13 | 审计与留存   | 会话、结果、阈值、设备、删除与留存策略可审计                  |
| FR-14 | 异步任务     | OCR、1:N 等长任务支持异步与回调                               |

## 3. 不在本期范围

- 证件真伪鉴定（全息、UV、纸张纹理、芯片读取）。
- 跨租户 1:N 检索。
- 人工复核后台与运营工作台。
- 商业 SDK、云厂商人脸 API、按次计费服务。
- 业务用户登录、账户体系与业务放行逻辑。
- 替代持牌实名渠道或法定实名认证。

## 4. 角色与场景

| 角色     | 场景                                                  |
|----------|-------------------------------------------------------|
| 业务用户 | KYC 首次认证、提现、改密、大额支付、绑定/解绑支付方式 |
| 业务 App | 集成统一 RN 组件，展示采集与结果                      |
| 业务后端 | 校验用户、签发 JWT、决定场景与 gallery、消费结果令牌  |
| 平台运维 | 租户开通、模型版本、阈值、留存与配额管理              |
| 平台审计 | 查询会话、结果、删除与异常记录，不读取特征明文        |

## 5. 非功能需求

| 类别   | 要求                                                               |
|--------|--------------------------------------------------------------------|
| 安全   | JWT 验签、jti 一次性、challenge 绑定、租户隔离、特征加密、日志脱敏 |
| 性能   | 同步核验 P95 不超过 3 秒；1:N 与 OCR 可异步                        |
| 可用性 | 模型不可用时快速失败，不降级为“通过”；提供健康探针                 |
| 可观测 | 请求 ID、租户、场景、耗时、分数区间、错误码、活体结果              |
| 合规   | 单独同意、最小化采集、留存期限、删除接口、租户级密钥               |
| 可扩展 | 引擎、向量索引、OCR 均通过接口隔离，可替换                         |

## 6. 验收标准摘要

1. 业务后端能签发 JWT，App 能凭 JWT 完成 challenge、采集、match/verify，并拿到可消费的结果令牌。
2. 无状态 1:1、活体、enroll/verify、1:N、证件 OCR 五条链路均有可重复的本地验证方式。
3. 过期、重放、越权、无脸、多脸、活体失败、比对失败、OCR 低置信均有明确错误码与审计。
4. 租户 A 无法读取或检索租户 B 的档案与 gallery。
5. 删除接口能清理档案、特征、索引与按策略可删除的图片。
6. 生产配置无法启用 DevToken 或 DevBypass。
7. 文档、接口契约、SQL 与错误码保持一致。

## 7. 约束与依赖

- 后端使用 Java 25（最低标准）/ Spring Boot 3.5.x，标准 Maven 多模块构建（`pom.xml` + `mvnw`）；人脸引擎使用 mica-ai-face（YuNet + SFace + MiniFASNetV2）；OCR 使用 mica-ppocr。
- 向量检索首期使用 PostgreSQL + pgvector（SFace 128d）。
- 生产部署在 Linux glibc 环境；开发可在 macOS 运行（openpnp 提供 macOS 原生库）。
- 依赖业务后端签发 JWT、提供用户身份与业务场景；平台不保存业务用户资料。
- 依赖 PostgreSQL、Redis；密钥库落库（主密钥环境变量注入）；对象存储本地 RustFS、线上 Cloudflare R2（S3 兼容）。
