## 1. 要解决的问题

在免费开源约束下，建设一套内部多业务共用的人脸核验服务，同时满足：

- KYC 人证 1:1 与敏感操作人脸 1:1；
- 静默活体，不能只做照片比对；
- 多租户隔离、短期 JWT、可审计；
- 1:N 检索与证件 OCR 的扩展能力；
- 服务端生产部署在 Linux，客户端只做采集，不引入端侧模型。

## 4. 调研证据

mica-ai 证据来自官方 GitHub 仓库 README（lets-mica/mica-ai，2026-11-14 核对）：Apache-2.0，29 stars，5 forks；运行时为 ONNX
Runtime 1.18.0 + OpenCV 4.9.0（openpnp），Spring Boot 2.7.x～4.x 兼容，JDK 8+。

| 组件                                                              | 许可证                    | 关键能力                                                                                                                                                                                                                               |
|-------------------------------------------------------------------|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [mica-ai-face](https://github.com/lets-mica/mica-ai)              | Apache-2.0                | `FaceDetector`（YuNet，人脸框+5 关键点）、`FaceAligner`、`FeatureExtractor`（SFace，128d L2 归一化）、`LivenessDetector`（MiniFASNetV2，real/replay/print）、`FaceVerifier`（1:1，默认阈值 0.35）、`AvatarExtractor` / `CardExtractor` |
| eDifFIQA-Tiny 模型                                                | CC-BY-4.0                 | 人脸质量分（0~1）；商用允许，**再分发必须署名**                                                                                                                                                                                        |
| [mica-ppocr](https://gitee.com/dreamlu/mica-ppocr)                | 待核验（Apache/MIT 倾向） | PP-OCR 纯 ONNX Runtime Java 推理，兼容 PP-OCRv4；落地前核对仓库 LICENSE                                                                                                                                                                |
| pgvector                                                          | PostgreSQL License        | PostgreSQL 向量索引（HNSW + cosine）                                                                                                                                                                                                   |
| [RustFS](https://github.com/rustfs/rustfs)                        | Apache-2.0                | 本地开发 S3 兼容对象存储；线上为 Cloudflare R2                                                                                                                                                                                         |
| [Kotlin Toolchain](https://github.com/JetBrains/kotlin-toolchain) | Apache-2.0                | JetBrains 统一项目管理与构建工具（Amper 演进）：`kotlin` CLI + `project.yaml`/`module.yaml`，内置 Spring Boot 支持，Maven Central 依赖可用；2026-11-14 约 513 stars，**状态 Alpha（0.13，2026-10）**                                   |

关键配置与默认值已核对（`mica.ai.face.*`）：

- 模型路径 `model.detection.path` / `model.recognition.path` 必填，`model.liveness.path` 在活体开启时必填；模型不入
  jar，缺失即启动失败（fail-fast）。
- `detection.threshold=0.9`、`detection.nms-threshold=0.3`；`liveness.threshold=0.85`、`liveness.crop-scale=2.7`；
  `verify.threshold=0.35`（多脸策略 `LARGEST_AREA` / `LARGEST_SCORE` / `REJECT`）。
- `onnx.device` 支持 CPU/GPU，可配置线程数与图优化级别。
- SFace 输出固定 128d，pgvector 列维度与启动探测必须一致。

## 5. 采用方案（v2）

**JDK 25（最低标准）/ Spring Boot 3.5.x（标准 Maven 多模块构建）+
mica-ai-face-spring-boot-starter（YuNet + SFace + MiniFASNetV2）+ mica-ppocr + MyBatis-Plus + PostgreSQL/pgvector +
Redis；对象存储本地 RustFS、线上 Cloudflare R2（S3 兼容，AWS SDK for Java v2）。**

理由：

1. 符合技术栈决策（Java + Spring Boot + 标准 Maven），与公司 Java 工程体系一致维护；依赖版本由 parent POM 集中仲裁。
2. mica-ai-face 一体化覆盖检测、对齐、128d 特征、静默活体与头像/证件卡片提取，纯 ONNX Runtime、零 Python 进程，首期不需要自行拼装多套模型。
3. 许可证清晰：核心 Apache-2.0，活体模型 MIT；唯一例外 eDifFIQA-Tiny（CC-BY-4.0）为可选能力，商用需署名，可在首期不启用。
4. mica-ppocr 与 mica-ai 同源（net.dreamlu），PaddleOCR ONNX 推理避免 Python sidecar，与 OCR 模板解耦。
5. pgvector 与 PostgreSQL 同库，减少首期组件数量；RustFS/R2 同一 S3 兼容实现，本地与线上零切换成本。

## 6. 排除理由（v2 汇总）

| 方案                            | 排除原因                                                          |
|---------------------------------|-------------------------------------------------------------------|
| C# + ViewFaceCore + SeetaFace6  | 与技术栈决策冲突（切换为 Java/Spring Boot）；v1 评估记录见第 8 节 |
| InsightFace SCRFD/ArcFace 权重  | 代码 MIT，但官方预训练权重为研究限制，不能直接商用                |
| Faceplugin / kby-ai / FaceAISDK | 引擎要求按 applicationId 购买 license，或无 LICENSE 文件          |
| CompreFace                      | 不含活体，且是多容器 Java + Python 架构；模型许可证需逐个核对     |
| Go 自组装                       | 无一体化库，首期开发量与活体调优成本高                            |
| 商业云 API                      | 违反免费开源约束                                                  |

## 7. 风险与观察项（v2）

| 风险                        | 说明                                                                        | 应对                                                                                                                              |
|-----------------------------|-----------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| mica-ai-face 社区较新       | 约 29 stars，问题参考少，API 与模型可能变化                                 | 锁定版本、审读关键源码、建立升级评估与回归测试；必要时可通过 `FaceEngine` 接口整体替换引擎                                        |
| Kotlin Toolchain（已移除） | Alpha 构建工具成熟度低，双构建存在漂移风险 | **v2.2 已移除 KT，统一标准 Maven 构建**，风险消除 |
| 活体泛化                    | MiniFASNetV2 为轻量单帧模型（80x80），对屏幕翻拍、打印、Deepfake 的泛化有限 | 挑战动作、频控、设备风控、人工复核；多帧投票提升稳定性                                                                            |
| 1:N 误识别                  | gallery 越大，误命中后果越高                                                | 阈值 + margin，接近阈值转人工，按 gallery 规模设上限                                                                              |
| 128d 特征区分度             | 维度低于部分大模型，阈值需实测校准                                          | `verify.threshold=0.35` 仅作初始默认，用真实样本校准后写入租户策略                                                                |
| OCR 真伪                    | OCR 只识别字段，不验证证件真伪                                              | 规则校验 + 人工复核，明确对外口径                                                                                                 |
| mica-ppocr 许可证           | 未直接核验仓库 LICENSE                                                      | 落地 OCR 前核对；不通过则退路为 ONNX Runtime + PP-OCRv4 det/rec ONNX 模型（Apache-2.0）自实现推理，接口 `DocumentRecognizer` 不变 |
| 合规                        | 人脸与证件均为敏感信息                                                      | 同意、加密、最小化、留存、删除、审计                                                                                              |
| 模型升级                    | 特征版本不一致会导致误判                                                    | `model_version` 版本化，重建索引后再切换                                                                                          |

## 8. 历史记录：v1 评估（2026-11-14，C# 路线）

v1 结论为 **C# / ASP.NET Core + ViewFaceCore(SeetaFace6) + RapidOcrNet + PostgreSQL/pgvector + Redis**，当时通过 GitHub
API 核对：ViewFaceCore MIT（998 stars）、SeetaFace6 BSD-2（680 stars）、RapidOcrNet Apache-2.0（106 stars）；关键默认值：
`FaceRecognizer` 阈值 Normal 0.62 / Mask 0.48 / Light 0.55，`FaceAntiSpoofing` 默认 `VideoFrameCount=10`、`clarity=0.3`、
`reality=0.8`，Linux 需 `FaceAntiSpoofingConfig.Global=true`（加载 `fas_first` + `fas_second`），活体进程内静态锁串行。

该路线已完成一轮 Mock 实现验证（单元 25/25、集成 15/15），2026-11-14 因技术栈决策切换为 Java/Spring Boot 而整体作废；Go
备选、CompreFace 与商业云 API 的排除理由延续至 v2。

## 9. 结论（v2）

采用 **Spring Boot 3.5.x + mica-ai-face + mica-ppocr + MyBatis-Plus + pgvector** 作为首期实现；`FaceEngine`
接口保证引擎可整体替换，seetaface6SDK 与 Go 自组装保留为替代路线。该结论只在许可证与 API 层面成立，活体与 1:N
的实际效果必须用真实设备和样本验收后再定阈值（初始默认：1:1 0.35、活体 0.85，1:N 待校准）。
